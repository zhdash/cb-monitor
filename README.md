# cb-monitor · 可转债成交额监控

A 股可转债的**日内资金博弈监控面板**：从全市场按成交额取前 20，实时跟踪 5 分钟 / 60 分钟两个周期的下跌形态，自动入池与剔除，并记录每一次进出的原因与数值。

> 面向日内交易者：只看波动、换手与资金节奏，不做长期持有判断。

## 功能

**① 全市场明细表**
按成交额排序，展示前 20 的：现价、涨跌幅、成交额、**溢价率**、成交量、最高、最低，支持点击查看 K 线、勾选自选。已公布强赎的债会打「强赎」小标（悬停显示公告日 / 赎回登记日 / 赎回价）。

**② 「5下跌」池** —— 5 分钟规则，**只算当天**，每 10 秒扫描

| | 规则 |
|---|---|
| 入池 | 从最新一根 K 线往前回溯，**只数当天的 K 线**（回溯到前一交易日即停）；这段里一路不出现上涨（收 ≤ 前收，**走平不算中断**），且**有 2 根单根跌超 0.25%**（不要求相邻）。当天第一根按**标准涨跌幅**（对比前一根收盘，基准可落在上一交易日）同样计入 |
| 排序 | 按「跌超 0.25%」的**根数降序**，显示「连跌达标 N 根」 |
| 剔除 ① | **涨破**：任一根**已收盘** K 线 收 > 前收 |
| 剔除 ② | **破位（实时）**：入池之后、且 ≥10:15 的**下跌** K 线，其**最低价** ≤ 入池时日内低点 ×(1+0.05%)。**含正在走的那根 —— 摸到新低即剔，不等收盘** |
| 剔除 ③④⑤ | 掉出成交额前 20 / 已公布强赎 / 手动移除 |

> **⚠️ 入池取样点 = 入池那一刻【已收盘的最后一根】K 线** —— 也就是让「连跌 N 根达标」成立的那根
> （`watchEntry[code] = times[lastClosedIdx(d)]`）。
> ⇒ **取样点那根【自身也参与】破位判定**（它就是「入池之后的第一根」K 线）。
> 所以「**入池即剔**」是正常现象 —— 入池那一轮若它自己已摸到新低，就会在**同一秒**写出 `in` + `out 破位`
> （流水里 10:30:37 微导/丰茂、10:40:04 联瑞/强达 都是这样）。这符合「下跌的 K 线摸到日内新低就剔」的定义。
> 只有「取样点恰好在走」（`i > end && i === ei`）时才跳过 —— 现在只剩**手动加入自选**那条路会走到（手动记的是墙钟时刻）。
>
> ⛔ **别改回「数据末根」（`d.times[d.times.length-1]`）** —— 那会拿到**正在走的那根**，
> 于是刚创出日内新低的那根 K 线被**双重豁免**：① 基准用「取样点前一根」算 → 把它算进基准；
> ② 检查范围从取样点之后开始 → 它自己不被判。**结果就是该剔的不剔。**
> 2026-09-30 振26转债 113709 实测：11:10 下跌 −0.173%、低 179.700 = 日内新低，
> 旧口径取样点记成正在走的 11:15 → 基准被拉到 179.700 → 不剔；改记 11:10 后 → 低 179.700 ≤ 基准 180.654 → 正确剔除。
>
> **破位只认最低价**，不要求收盘价也在新低；**基准**取「入池那一刻已确定的日内低点」，
> 且**不含取样点那根自己**（拿它自己的低点当基准等于自己跟自己比）、也**只用已收盘的 K 线**计算
> —— 正在走的那根的低点会继续下探，拿它当基准会把基准「追低」、导致永不剔除。
>
> **破位实时、涨破等收盘**：破位可用正在走的那根判定（腾讯 5 分钟 K 线的末根正是它，标签为其收盘时刻、盘中实时刷新），摸到新低即剔；涨破仍只认已收盘的 K 线，避免实时价来回抖动导致反复进出。**两者同一轮都成立时，先判涨破。**
>
> **自动剔除后要等一根「上涨」K 线**：某只债被自动剔除后，必须等它先走出**一根上涨的 5 分钟 K 线**，才允许重新入池 —— 既断掉「入池 → 立刻被剔 → 又入池」的循环，也符合行情语义（这一波下跌走完再重新看）。

**③ 「60下跌」池** —— 60 分钟规则，**不等收盘**，每 1 分钟复核

三条门槛需同时满足（全部实时）：
1. 最新一根 60 分钟 K 线本根累计跌幅 **≥ 1.9%**
2. 当天**没碰过、也没跌到** 60 分钟布林中轨下方（`low ≤ mid`）
3. 当天除第一根外，没有「下跌 K 线」触及当天最高价（`high ≥ 当天最高 ×(1−0.05%)`）

> 第一根（10:30）常是当天最高点来源，不参与第 3 条检查。

**④ 进出流水**
独立卡片记录最近 40 条入池 / 剔除（时刻 + 名称 + 原因 + 判定数值），localStorage 持久化。剔除往往是瞬时发生的，事后根本看不见，有它才能当场核对「谁 / 几点 / 因哪条规则 / 当时数值多少」。

**⑤ 非交易时段自动暂停（刷新 + 扫描）**
只在**交易时段**自动刷新与扫描；非交易时段**不发任何请求**（手动「立即」按钮不受影响），避免收盘后 K 线不再变化导致的无效空转与无谓流量。

> **判断依据（双保险）**：① **本地时钟** —— 周一~周五 `09:15~11:30`、`13:00~15:01`（收盘多留 1 分钟，确保取到 15:00 最后一根 K 线）；
> ② **行情状态 `lastMarket`** —— 为「休市」时不刷（覆盖法定节假日）。
> ⚠️ 不能只靠 ②：非交易时段不发请求就拿不到最新的 `lastMarket`，必须靠时钟兜底。
>
> **触发方式与频率**：定时器仍按设定的刷新间隔到点唤醒，但非交易时段**只做一次本地时钟判断就返回、不发请求**（零网络开销）；
> 交易时段按设定间隔正常刷新。开盘时间一到（时钟走进交易日 09:15）**自动恢复**，不需要手动操作。
> 收盘瞬间（15:02 起）自动进入暂停，两池状态栏会显示「非交易时段 · 自动刷新与扫描已暂停」。

## 运行

### 方式一：本机后端（默认）

```bash
python app.py          # 默认端口 8011
```

浏览器打开 <http://127.0.0.1:8011>。Windows 可双击 `start.bat`。无需安装第三方依赖，只用标准库。

### 方式二：纯静态托管（给多设备联网访问）

`app.html` 内置**数据适配层**：页面若从 `127.0.0.1:8011` 打开就走本机后端，从**任何其它地址**打开
就由浏览器**直接请求数据源** —— 所以整个工具可以当纯静态站发布，**不需要服务器**。

```bash
# 本地验证静态模式（任意静态服务器都行）
python -m http.server 8022
# 打开 http://127.0.0.1:8022/app.html
```

托管时只需上传 **`app.html`**、**`vendor/echarts.min.js`** 和 **`cb_list.json`**（入口地址 = `…/app.html`）。
`diag.html`（直连自检页）建议一并上传，排查问题时直接打开它即可逐项看结果。

> **直连可行性**（2026-09-30 实测，以下接口均返回 `Access-Control-Allow-Origin: *`）：
> 腾讯 `qt.gtimg.cn`（行情）、`ifzq.gtimg.cn`（5 / 60 分钟 K 线）、
> 东财 `datacenter-web.eastmoney.com`（可转债清单、强赎名单）。
> ⚠️ **溢价率**走东财 `push2.eastmoney.com`，其跨域支持**尚未确认** —— 静态模式下若拿不到，
> 该列会留空（`--`），**不影响其它所有功能**。
>
> ⚠️ **两种模式的数据完全等价**（已逐值比对：行情 318/318、K 线 OHLC / 成交量 / 布林线中轨全一致）。
>
> ⚠️ **池子与流水存在浏览器 localStorage，按域名隔离**：不同设备/不同地址**各看各的**，不会同步。
>
> ⚠️ 扫描逻辑本来就在浏览器里跑 —— 无论哪种模式，**都要有台设备的页面开着**才会自动筛。

## 说明

- 两池**共同铁律**：只收「成交额前 20」，掉出即剔；**已公布强赎的债一律不收**。
  ⚠️「前 20」用的是**页面行情快照**（`allRows`）。快照过期时扫描会**先补刷一次**（保质期 15 秒）——
  否则标签页在后台（`load()` 被 `document.hidden` 拦住）时会一直拿**上一交易日**的前 20 去扫当天，
  今天才爆量的债永远进不了名单（2026-09-30 振26转债 113709：昨天第 45 名 → 从未被扫描）。
- 判定**只用原始价格、不加容差**（涨 0.001 元也算涨）。显示层对微涨微跌保留 4 位小数并标注【涨 / 平 / 跌】，避免把「显示成 0.00%」误当成「没涨」。
- 本工具仅做数据整理与条件提示，**不构成任何投资建议**。

## 变更记录

### v1.2.1

- **失败不再静默**（2026-09-30 老大报「等了好久都没数据」）
  旧代码在直连模式下有两条静默失败路径，出问题时页面只剩「正在首次拉取…」，不留任何线索：
  ① `fetchCbList()`：清单接口偶尔返回 `{"result":null}`（上游抖动），旧代码 `if (!batch.length) break;`
  把它当成「清单为空」直接返回 `[]` → 整页 0 条；
  ② `directQuotes()`：各批行情失败都被 `catch` 成空串 → 0 行且 `error` 为空。
  现在：清单接口**单页失败重试一次**、首页为空**抛错**；行情批次**统计失败数**并把原因写进 `error`；
  空结果**不写缓存**（下一轮立刻重试）。
- **清单快照兜底**：新增同源 `cb_list.json`（320 只存续债）。上游清单不可用时自动回退到它，
  整页不再因为一个接口抖动而空白。
- **没有数据时就继续重试**：非交易时段原本「一发请求都不发」，页面在收盘后打开只有启动时那一次请求，
  一旦失败就**永远停在「正在首次拉取…」**（这才是「等了好久都没数据」的直接原因）。
  改为：**一条数据都没有时，无论是否交易时段都按间隔继续重试**；拿到数据后才真正按交易时段暂停。
- **页脚/控制台显示版本号与运行模式**（`v1.2.1 · 静态直连模式`）—— 排查时先确认「跑的是哪一版」。

### v1.2.0

- **支持纯静态托管**（多设备联网访问）：`app.html` 内置**数据适配层**，从 `127.0.0.1:8011` 打开走本机后端，
  从任何其它地址打开则由浏览器**直连数据源**（腾讯行情/K线、东财清单/强赎/溢价率）。
  判定逻辑一行未改，两模式数据逐值一致（行情 318/318、K 线 OHLC/成交量/布林线全一致）。
- ⚠️ **跨域请求不能带任何「非简单头」**：`fetch(url, {cache:'no-store'})` 会让浏览器附加
  `Cache-Control`，从而触发 CORS 预检；而**腾讯不支持预检**（OPTIONS 只回 `ACAO:*`，缺 `Allow-Methods`/`Allow-Headers`）
  → 真正的 GET 根本发不出去。三处跨域请求已改为**不带任何选项**，新鲜度靠自建 TTL 缓存。
  > 教训：`Access-Control-Allow-Origin: *` 只代表**支持简单请求**，不代表支持预检 —— 要用 OPTIONS 单独测。

### v1.1.3

- **扫描前先给行情快照保鲜**（`ensureQuotesFresh`）
  `load()` 开头有 `if (document.hidden) return;` —— 标签页在后台时行情快照**不再更新**；
  而自动扫描**不检查 `document.hidden`、照常每 10 秒跑**，于是它拿**上一交易日的 `allRows`**去算
  「成交额前 20」：昨天没量、今天才爆量的债永远进不了扫描名单（当日**从未被选中**），
  掉出昨天前 20 的债又会被误剔。
  修法：扫描（`autoWatchScan` / `scan60Watch`）开工前调用 `ensureQuotesFresh()` ——
  快照超过 **15 秒**就补刷一次（并发去重，失败沿用旧快照并在下一轮重试），
  保证「前 20」永远是**当天**的名单。
  > 实测铁证：入池 9 只债的遍历顺序与「前一交易日排名」严格升序吻合（1→5→9→10→11→15→17→19→20），
  > 与「当日排名」完全不符；后台标签页转前台后立刻自愈（不在昨日前 20 的债开始入池）。

### v1.1.0

- **连跌计数只算当天**（`cca7952` → `c1b8409`）
  回溯「一路不连跌」时不再跨到前一交易日；同时**保留当天第一根**的计数 ——
  只要它已收盘、标准涨跌幅跌超 0.25% 就算下跌（它的基准落在上一交易日，属标准涨跌幅口径，不算「跨日串根」）。
  修复现象：节后首日早盘「当天只走出 5 根、却显示连跌达标 7 根」的虚高。
- **破位剔除改为实时判定**（`3b76355`）
  下跌的 5 分钟 K 线只要在 10:15 后摸到新低即剔除，**不必等它收盘**（判定范围含正在走的那根）。
  基准仍**只用已收盘的 K 线**计算，避免被正在走的那根的实时低点「追低」而永不触发。
- 涨破、5 分钟中轨标记、入池判定、60 下跌池 —— **口径均未改动**。

### v1.0.0

- 首个版本：全市场成交额前 20 明细表（含转股溢价率）、「5下跌」/「60下跌」两个自选池、
  进出流水（独立卡片，localStorage 持久化）、已公布强赎排除、收盘后自动暂停扫描。
